/player.html — Player controls

Players can open /player.html and log in by choosing their player name and entering their token. The page also continues to support direct links containing the configured player ID and token:

http://SERVER-IP:3000/player.html?id=john&token=PLAYER_TOKEN

The page lets the player choose from their assigned games, change production status, and see whether production has marked them Off Air, Stand By, or Live.

Changing games clears the previous production request. The page reconnects and re-authenticates automatically if its WebSocket connection drops.

Player tokens are credentials. Direct tokenized links should not be posted publicly. After a successful direct-link login, the page removes the credentials from the browser address bar.

/dashboard.html — Production dashboard

The dashboard is the main administrative view. It requires the production admin key.

It shows player game/status/connection information and provides controls for changing a player's current game, Stand By, Live, Off Air, status clearing, panic reset, event reset, and compact-monitor mode. It also displays server and player connection health.

/compact.html — Compact monitor

A distance-readable 640×360 display intended for quick production or host reference. It has no local controls.

ModeShows
priority / CALLSASAP and Soon requests
normalNormal players
bkDowntime / no-progression players
allAll players

Soon calls flash briefly when first received. ASAP calls continue flashing until that request has been taken live. The display shows up to five rows and reports additional matching players as +N MORE.

A non-flashing alternative is available at /compact-noflash.html; it uses the same layout but keeps ASAP/Soon rows highlighted instead of animating them.

/overlay.html — Player overlay

A transparent browser-source graphic for a single player.

http://SERVER-IP:3000/overlay.html?id=john
http://SERVER-IP:3000/overlay.html?id=john&status=0

id selects the player. Adding status=0 hides production-status text and leaves the player name and current game.

Real-time updates

The player, dashboard, compact, and overlay pages update through the server's WebSocket connection at /ws. The landing page does not use WebSocket.

For message formats, authentication, HTTP endpoints, and production automation, see the API Reference.
