Application Overview

Archipelago Broadcast Control serves a small set of purpose-built pages for players, production staff, multiview monitoring, and viewer-facing graphics.

All pages are static HTML/CSS/JavaScript files served by the application itself. Pages that need live state connect to the server's standard WebSocket endpoint at /ws and react to state.snapshot updates.

Scope: This document covers HTML pages intended to be opened in a browser or browser source. API endpoints and the WebSocket protocol are documented separately.

Base URL

On a local production network:

http://SERVER-IP:3000

Example:

http://192.168.1.50:3000

All page URLs in this document are relative to that base URL.

PLAYER AUTH/player.html

Player Broadcast Controls

The player page is the primary interface each participant uses during the event. It is designed to minimize player workload while providing production with current-game and editorial-intent information.

Required Query Parameters

ParameterRequiredDescription
idYesConfigured player ID.
tokenYesAuthentication token configured for that player.

Example URL

http://192.168.1.50:3000/player.html?id=alan&token=PLAYER_TOKEN

Player Interface

Current GameA dropdown containing only the games assigned to the authenticated player.
Production StatusLarge buttons generated from the configured status definitions.
Broadcast IndicatorDisplays NOT ON AIR, STAND BY, or YOU'RE LIVE.
Connection FeedbackShows connection/reconnection and command-result messages.

Current Game Behavior

Changing the game sends the player.game WebSocket command. The server also resets the player's production status to Normal and clears any prior ASAP acknowledgement.

Status Behavior

Status buttons are generated from config.json. In the current example configuration they include:

StatusTypical Meaning
NormalNo special production request.
Interesting SoonSomething worth showing is approaching.
Please Show Me ASAPProduction should prioritize this player.
Downtime / No ProgressionAvoid this player unless necessary.

Air-State Feedback

Server StatePlayer Display
offNOT ON AIR
standbySTAND BY
liveYOU'RE LIVE

Connection Behavior

The included WebSocket client automatically reconnects. After reconnection, the page automatically re-authenticates using the player ID and token from the URL.

Security: Because the token is part of the URL, player links should be treated as credentials and should not be posted publicly.

ADMIN AUTH/dashboard.html

Production Dashboard

The full production dashboard is the administrative control interface for monitoring players and changing their production state.

URL

http://SERVER-IP:3000/dashboard.html

Authentication

The page prompts for the server's production/admin key. Successful authentication unlocks both the player cards and compact-monitor mode controls.

Player Card Information

Each card displays:

  • Player name
  • Current game
  • Current production status
  • Whether the player control page is connected
  • Status age, when applicable
  • Current air state when not off-air

Player Controls

ButtonAction
Stand bySets the player's airState to standby.
Take liveSets airState to live; any previously live player is automatically set off-air.
Off airSets the player's airState to off.
Clear statusReturns the player's production request to Normal.

Compact Monitor Controls

The dashboard also changes the server-wide display mode used by /compact.html:

ButtonCompact Mode
Callspriority — ASAP and Soon only.
Normalnormal
BKbk — downtime/no-progression players.
Allall

Sorting

The dashboard sorts players by live state and player-reported priority, making active or urgent players easier to find.

Reconnect Behavior

If an already authenticated dashboard reconnects, it automatically attempts to re-authenticate with the production key held in the page's JavaScript memory.

PRODUCTION DISPLAY/compact.html

Compact Production Status Monitor

A dedicated, distance-readable status display designed around a 640×360 window.

URL

http://SERVER-IP:3000/compact.html

Default Mode

The default mode is CALLS, which shows only players in asap or soon status.

Available Modes

ModeDisplay LabelPlayers Shown
priorityCALLSASAP + Soon
normalNORMALNormal status
bkBKDowntime / BK
allALLAll players

Mode Control

The page has no local controls. Its mode is changed remotely through the production dashboard or the admin.compact.mode WebSocket command. All open compact views update together.

Row Information

Each row contains:

  • Large status label: ASAP, SOON, BK, or OK
  • Player name
  • Current game
  • Age of the current non-normal status
  • LIVE appended to the status when the player is currently on-air

Attention Behavior

  • Soon: flashes for approximately 5.2 seconds after a new request, then remains static.
  • ASAP: flashes continuously until that specific request has been taken live.
  • ASAP after being served: does not start flashing again simply because the player later goes off-air.
  • New ASAP request: begins flashing again.

Capacity and Overflow

The compact monitor displays a maximum of five large rows. If more players match the current mode, the footer displays +N MORE rather than shrinking all rows.

Empty States

ModeEmpty Message
CALLSNO CALLS
Other modesNONE

Connection Indicator

The footer displays LIVE when connected to the server and DISCONNECTED when the WebSocket connection is down.

PRODUCTION DISPLAY/multiview.html

Status-Aware Multiview Mockup

This page provides a grid of placeholder video tiles showing how production metadata can be integrated into a real multiview.

URL

http://SERVER-IP:3000/multiview.html

Displayed Metadata

Each tile may show:

  • Player name
  • Current game
  • Production status badge when status is not Normal
  • STANDBY or LIVE badge when the player's air state is not off
  • Priority-dependent border styling

Intended Use

This page is a metadata/layout mockup, not a video router. The tiles do not ingest or display real gameplay video. It is intended to guide or supplement integration with the production system's actual multiview.

Real-Time Behavior

The grid rebuilds from each state.snapshot received from the WebSocket server. No authentication or user interaction is required.

GRAPHICS/overlay.html

Per-Player Overlay

A transparent HTML overlay intended for use as a browser source or lower-third style graphic.

Required Query Parameter

ParameterRequiredDescription
idYesPlayer ID whose metadata should be displayed.

Optional Query Parameter

ParameterValueDescription
status0Suppresses the production status text.

Examples

Show player, game, and non-normal production status:

http://SERVER-IP:3000/overlay.html?id=alan

Show only player and game:

http://SERVER-IP:3000/overlay.html?id=alan&status=0

Displayed Fields

  • Player name
  • Current game
  • Human-readable status label when status display is enabled and the status is not Normal

Transparency

The page background is transparent, allowing it to be placed directly over video in OBS, vMix, or another browser-source capable graphics system.

Behavior

The overlay listens to state.snapshot, selects the player matching the id parameter, and updates automatically whenever their current game or status changes.

Viewer-facing recommendation: Use status=0 for a normal lower third unless production-status information is intentionally meant to be visible to viewers.

Caching

Operational caution: Browser sources can cache CSS and JavaScript aggressively. After application updates, perform a hard refresh or version static asset URLs to avoid stale behavior.

Page Troubleshooting

Page Loads but Does Not Update

  1. Open browser developer tools.
  2. Confirm the JavaScript files return HTTP 200.
  3. Check the Console for JavaScript errors.
  4. Check the Network → WebSocket panel for a connection to /ws.
  5. Confirm a state.snapshot is received after connecting.

Player Page Shows an Error

Verify that both id and token are present and match config.json.

Production Dashboard Connect Button Fails

Verify the admin key, confirm the WebSocket is connected, and look for the auth.admin request and corresponding ack in developer tools.

Compact or Overlay Shows Old Styling

Hard-refresh the page or clear the browser-source cache. A cached stylesheet can make the rendered page appear inconsistent with the current JavaScript/server state.

Deployment Notes

All pages are served from the application's public/ directory by the same Node.js server that hosts the HTTP API and WebSocket endpoint.

For a local production network, use the server's LAN address. For internet deployment, place the application behind HTTPS/WSS and apply appropriate access controls, especially for player URLs containing tokens and the admin-facing dashboard.
